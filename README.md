 +## Архитектура (коротко)
 +
 +- Локальная БД хранит пользователей, серверы, привязки, ручные и общие подписки. Источник правды
 +  по VPN-конфигам остаётся за панелями Hiddify; приватные ключи у нас **не хранятся**.
 +- Один локальный пользователь имеет разные UUID на разных серверах (привязка `(ServerId, Uuid)`).
 +- Витрина рендерится как статический SSR-компонент без Blazor-circuit — открывается быстро и
 +  работает даже при недоступном SignalR. QR генерируется на сервере (QRCoder).
 +- Админка спрятана за секретным путём `/{guid1}/{guid2}/…` (первый барьер) и закрыта
 +  cookie-аутентификацией с паролем (PBKDF2). Без авторизации — редирект на логин; обращение к
 +  админ-путям без секрета — нейтральный 404.

 +## Агрегированная подписка
 +
 +Ссылка `/u/{token}` работает двумя способами и различает их по заголовкам запроса:
 +
 +- **Браузер** (`User-Agent: Mozilla/…` + `Accept: text/html`) получает страницу витрины.
 +- **VPN-клиент** получает одну подписку, собранную из всех подписок этого пользователя —
 +  привязок к серверам Hiddify, ручных и общих ссылок.
 +
 +Принудительно переключить режим можно параметрами `?page=1` и `?sub=1`.
 +
 +Как это работает:
 +
 +- Сервис запрашивает подписку у каждого провайдера и склеивает ответы в один массив.
 +  Записи переносятся без изменений, поэтому сохраняются балансировщики, персональные правила
 +  роутинга провайдеров и протоколы вроде hysteria2. Меняется только отображаемое имя сервера:
 +  к нему добавляется префикс источника.
 +- **Каталог провайдера зависит от User-Agent.** Некоторые панели отдают неполный набор серверов
 +  или вовсе отказывают незнакомым клиентам, поэтому наружу сервис представляется значением
 +  `Aggregation__UserAgent` (по умолчанию Happ), а на каждом источнике UA можно переопределить.
 +  Подобрать его помогает кнопка «Проверить агрегат» — она показывает, сколько записей вернул
 +  каждый провайдер.
 +- **HWID синтетический и постоянный для источника.** Панели с лимитом устройств считают их по
 +  заголовку `X-Hwid` при скачивании подписки, поэтому провайдер видит одно устройство независимо
 +  от числа реальных устройств пользователей. Само VPN-подключение никакого HWID не передаёт.
 +  Ограничением остаётся лимит одновременных подключений на стороне провайдера.
 +- **Ответы кэшируются** (`Aggregation__CacheTtlMinutes`, по умолчанию 10 минут) и сохраняются
 +  в БД. Если провайдер недоступен, отдаётся последний удачный снимок — серверы не пропадают
 +  из клиента. Если данных нет вообще, сервис возвращает 502, а не пустой список: пустой ответ
 +  некоторые клиенты применяют и стирают уже настроенный профиль.
 +- **Правила группировки** (`Aggregation__GroupRules`) сводят однотипные серверы разных
 +  провайдеров под общее имя с нумерацией и выводят их одним блоком. Блок вставляется после
 +  первых `Aggregation__GroupInsertAfter` обычных серверов (по умолчанию 20), а если их меньше —
 +  после всех.
 +
 +Формат ответа — массив конфигов, который понимают INCY и Happ. Клиенты, работающие только
 +с base64-списками ссылок или Clash/sing-box, эту подписку не примут.
 +
 +## Конфигурация
 +
 +Все секреты задаются через переменные окружения (см. [`.env.example`](.env.example)):
 +
 +| Переменная | Назначение |
 +|---|---|
 +| `Admin__SecretPathSegment1` / `…Segment2` | Два GUID-сегмента секретного пути админки |
 +| `Admin__PasswordHash` / `Admin__PasswordSalt` | PBKDF2-хеш и соль пароля админа (base64) |
 +| `ConnectionStrings__DefaultConnection` | Строка подключения SQLite (в Docker по умолчанию `/data/vpndashboard.db`) |
 +| `Ping__IntervalMinutes` / `…TimeoutSeconds` / `…Enabled` | Параметры фонового пинга (необязательно) |
 +| `Aggregation__HwidSecret` | Ключ синтетического HWID для запросов к провайдерам. Пусто — берётся соль пароля админки |
 +| `Aggregation__UserAgent` | User-Agent по умолчанию при запросе подписок (необязательно) |
 +| `Aggregation__CacheTtlMinutes` / `…Enabled` | Параметры агрегатора подписок (необязательно) |
 +
 +### Сгенерировать хеш пароля
 +
 +```bash
 +dotnet run --project VpnDashboard -- hash-password "ВАШ_ПАРОЛЬ"
 +# выведет строки Admin__PasswordHash=… и Admin__PasswordSalt=… — скопируйте в .env
 +```
 +
 +В контейнере (ENTRYPOINT уже `dotnet VpnDashboard.dll`):
 +
 +```bash
 +docker compose run --rm --no-deps vpndashboard hash-password "ВАШ_ПАРОЛЬ"
 +```
 +
 +### Секретный путь
 +
 +Сгенерируйте два GUID (`uuidgen`, онлайн-генератор и т.п.) и впишите в `Admin__SecretPathSegment1/2`.
 +Админка будет доступна по `https://ваш-хост/{seg1}/{seg2}/`.
